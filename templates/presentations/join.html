The form had no `action` and no `method`, and the only route to the session was `location.href = "/live/join/" + code + "/"` built by hand in JavaScript. With JS blocked or still loading, submitting did nothing — it just reloaded the page with the code in the query string. The URL was also hardcoded, so renaming that route in urls.py broke joining with no error anywhere. 2. A bad code produced `alert("Please enter a valid 6-digit code.")`. On a phone that is a modal the person has to dismiss before they can even see the field they got wrong. 3. The input accepted any characters and was only checked on submit, so you could type six letters and be told off afterwards. 4. Nothing handled a pasted join link, which is the most common way someone gets a code — they copy the whole URL out of a chat message. This version posts to a named URL and works with JavaScript disabled. The script is enhancement only: it filters input, accepts a pasted link, and shows the error inline. Set `join_code_url` to whatever your route is actually called. The view should read `code` from POST, and re-render with `error` on a bad code. {% endcomment %} {% block content %}
